# P0-M5A — 长期模拟引擎补充决策与科学验收

状态：设计补充；基线参照 `docs/P0-M5_LONG_HORIZON_SIMULATION_SPEC.md`；尚未实施。该文不覆盖已有M5设计，所有冲突以显式设计评审决议为准。

## 目标与界限
实现可暂停、可存档、可恢复的REBOUND IAS15四体牛顿引力长期计算，允许碰撞终止、行星高速飞掠和逃逸候选，不提供不存在的碰撞后物理。M5A为计算服务及数据接口；Web控制台归属M5B。必须与已合并G2/G2.1、M2、M3、M4、VIS1、VIS2的实际归档模式兼容；不要以未合并PR代码冒充main契约。

## 开发前必须裁决的设计事项
1. **REBOUND 归档可恢复性**：明确实际使用的REBOUND版本、`Simulation.save_to_file`和加载API，编写最小可运行实验验证IAS15内部状态、`t`、`dt`、粒子顺序、`G`和单位能被正确恢复。Python callback不能假定被序列化；必须重挂并恢复observer状态。
2. **暂停时刻与一致性**：首版仅允许在安全输出目标/确定性segment边界暂停，或明确区分内部heartbeat checkpoint与科学时间网格；wall-clock影响调用切割，不得默默改变物理integration target。检查点写入本身不能导致不同物理轨迹时序。
3. **恢复保证等级**：同REBOUND和平台的二进制精确续算与跨环境“科学等价”分开验收；混沌系统禁止用多年后坐标严格逐点一致作为唯一要求。记录最大能量漂移、角动量、局部短时轨道差、事件顺序与覆盖。
4. **磁盘与存储策略**：明确最大检查点数量、快照间隔、磁盘配额、GC、段索引和保留审计证据的策略。保留最新一个检查点不足以保证损坏回退；需要可验证至少N个历史快照策略。
5. **独占写入与故障处理**：明确跨进程锁的失效检测、审计与手动恢复，不允许因PID复用/时钟误差自动删除活锁。测试临时目录、fsync、rename、hash校验失败。
6. **API状态机**：PENDING → RUNNING → PAUSING → PAUSED → RUNNING，和 COMPLETED/COLLISION/FAILED 终态；重试应幂等，用户取消与物理碰撞必须有不同结果码。强制终态禁止随意恢复。
7. **跨段事件持续性**：`ESCAPE_CANDIDATE`的向外速度/比能/持续时间状态、close encounter去重、碰撞callback参与者、累计能量基准和sample/event全局编号必须恢复。
8. **数据适配**：SegmentedTrajectoryReader提供既有M2逻辑时间序列；M3/M4不能读取尚未提交的段，不能重复计算/重复事件；VIS2支持页面分块和事件跳转而非一次性加载全部历史。

## 可衡量验收矩阵
- A01 同一短期初态连续积分与分段保存/恢复，在相同物理目标时间序列下，对比每个目标的坐标、速度、累计守恒诊断和事件ID；设置明确的绝对/相对容差并报告依赖库版本。
- A02 连续100年对分段10+90年的验证：若高度混沌导致长期相位散开，必须报告Lyapunov敏感性/早期偏差及能量、角动量、事件结果，而不能虚报“完全一致”。
- A03 运行配额耗尽→PAUSED→resume；重复resume不会产生重复边界样本、事件或多个活动写入者。
- A04 故障注入覆盖临时段写入、checkpoint写入、rename、manifest更新、最新指针更新、断电模拟；恢复只认可完全提交的链。
- A05 四体碰撞于段边界前后、初始G2接触、仅逃逸候选、积分FAIL的各个状态均有明确归档并不伪造后续。
- A06 50万+逻辑样本的段读取/查找占用有界内存；可显示端点和事件邻近样本而不损失原始数据的科学意义。
- A07 REBOUND版本差异和损坏二进制检查点都被拒绝恢复，不能从四体JSON轨迹直接重置IAS15冒称无损。
- A08 M2/M3/M4/VIS1/VIS2及G2.1既有回归全部通过；CI Python3.11/3.12；真实长期基准单独运行并记录 wall time、峰值RSS、大小、守恒值。
- A09 严格区分SI物理秒、行星自转定义的昼夜、输出采样间隔和UI播放速度；“地球标准日”只作显示换算而不是三恒星世界唯一的一天。
