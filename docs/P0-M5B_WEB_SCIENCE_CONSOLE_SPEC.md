# P0-M5B — Web科学实验控制台实施规格

状态：新增原始P0-M5范围的补充规格。依赖M5A稳定的REST/任务服务契约，可先以现有M2/M3/M4运行记录开发只读浏览。**不在M5A中混入前端**。

## 产品职责
Web是世界科学实验控制面：设置随机初态及G2.1速度/距离阈值→验证配置→生成候选→选择世界→启动/暂停/恢复长期积分→查看已提交轨道、辐射、C0/C1温度、M4事件→比较多世界→导出可追溯报告。可视化复用VIS2；不在Web内计算牛顿四体物理或用JS重算温度。

## 功能边界与优先级
- B01 科学配置UI：载入和保存实验配置，严格显示SI原始字段与可选AU/太阳质量等展示单位；显示G2.1 `unrestricted` vs `bounded`、速度上限、最近恒星最大距离、随机宿主权重、偏心率与相位分布。所有输入统一经过后端校验并呈现字段级错误，不得在前端静默裁剪物理参数。
- B02 候选实验管理：由seed/index/hash生成可复现世界、展示筛选和初始接触、保留被认为不稳定/不宜居的世界；列表提供运行事件和结果计数。不得默认只展示“存活”世界。
- B03 任务控制：创建/启动/请求暂停/恢复/取消/查看进度；显示物理时间t_s、墙钟耗时、估算进度、不确定状态、资源限制、连续段/检查点数。命令异步且幂等；按钮调用后只显示PENDING直到服务端确认，不能假装即时暂停成功。
- B04 联动视图：嵌入/改造VIS2的3D四体轨道+恒星辐射+C0/C1与M4时间线；支持长时间轨迹分段按需读取、跳到事件、观察速度不改变求解器t；碰撞终态与数据空窗显式显示。无需把亿级原始点一次塞给浏览器。
- B05 实验对比和导出：按world_id、seed、物理版本、运行窗口筛选对比，展示能量守恒、热能闭合、事件数、初始参数、约束尝试记录及导出科学报告。数据来源和哈希可追踪。
- B06 安全与运营：首版限定本地/单用户或明确认证模式，任务/API参数做后端鉴权和路径校验；执行命令采用明确参数映射，绝不能将用户YAML用于shell/eval；单运行任务单写者，配额、取消、错误日志、重复提交和数据隔离均有测试。

## 推荐技术结构
`web-ui`前端与`experiment-api`后端隔离，`simulation-worker`调用Python计算模块，`artifact-store`储存不可变segment/checkpoint/thermal/outcome产物。
API只返回已提交（committed）数据：实时任务状态可更新，但科学结果永远来自可验证归档。第一版可用单机任务worker与SQLite状态库；无须立即做多服务器一致性、多租户或多人实时游戏。

建议REST端点（实施时必须版本化并有OpenAPI/schema）：
```
POST /api/v1/experiments/validate
POST /api/v1/worlds/generate
GET  /api/v1/worlds?seed=&status=&outcome=
POST /api/v1/runs
GET  /api/v1/runs/{run_id}
POST /api/v1/runs/{run_id}/pause
POST /api/v1/runs/{run_id}/resume
POST /api/v1/runs/{run_id}/cancel
GET  /api/v1/runs/{run_id}/segments
GET  /api/v1/runs/{run_id}/events
GET  /api/v1/runs/{run_id}/trajectory?start_s=&end_s=&max_points=
GET  /api/v1/runs/{run_id}/environment?start_s=&end_s=
GET  /api/v1/runs/{run_id}/manifest
```
任务突发/重复点击要求幂等键；控制动作以状态机判定允许转移，拒绝重复运行同run的并发写入；可用短轮询，WebSocket不应成为第一版必要前置。

## 身份与时间
- 当前物理时间始终为REBOUND绝对`t_s`。Web“1×、60×、3600×”仅改变回放或观察速度；计算任务运行速率由服务器资源和安全检查控制，不对用户保证现实1秒推进多少模拟年。
- 星球“昼夜”由自转轴/自转相位与各恒星的局部光照方向产生，不能用地球24小时作为世界日。
- 实验状态、用户指令和观察事件分离。世界毁灭可展示，但碰撞后物理状态标注终止，不合成虚构后续轨道。
- 禁止错误绑定：所有视觉M2/M3/M4流必须检查world_id、initial-state hash、segment/source hashes、同一SI时基和有效覆盖。

## 产品验收场景
C01 使用界面创建一个`bounded` G2.1世界，显示随机宿主、距离、初速度和与逃逸代理速度比值；同seed可复现。
C02 创建`unrestricted`高速飞掠世界，不因逃逸/不宜居被静默剔除。
C03 提交模拟→暂停→刷新浏览器→恢复→完整继续；观测历史不重复，仍可以从别的浏览器窗口打开同一只读报告。
C04 一次重试/连续点击不会创建两个运行同一run的worker，资源配额和错误状态正确显示。
C05 行星与恒星碰撞及恒星间碰撞能被准确区分，原始M2终止时间后没有虚假科学轨迹。
C06 VIS2各面板时间轴同步、C1缺失时明确展示空数据；M4标注不等于气候证明。
C07 有大量轨迹样本时，API按范围分页，UI最多请求有限点数，时间轴仍支持准确事件跳转。
C08 完整端到端流程：配置→生成→积分→辐射/温度→世界分类→联动观察→导出；自动化浏览器测试与API测试通过。
C09 任务控制异常（超时、进程崩溃、坏checkpoint、旧版本、磁盘配额）在UI有可诊断信息，不把操作失败宣称为完成。

## 阶段计划
M5B-01 信息架构+API模型+只读实验/世界列表；
M5B-02 安全配置编辑、校验、可复现候选创建；
M5B-03 任务状态与作业调度、幂等控制、暂停恢复；
M5B-04 VIS2分段展示、事件跳转、温度辐射联动；
M5B-05 世界比较、可追溯导出、性能/可访问性/浏览器端到端；
M5B-06 首版运维规范、资源限制、异常演练和发布验收。

## 明确不包括
多人实时宇宙同步、地表第一人称漫游、生命文明模拟、云分布式运算、完整气候模型与碰撞后恒星演化；它们属于P1以后。M5B首版是科学实验控制台，不是完整游戏客户端。
